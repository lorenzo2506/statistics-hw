HMWK 2 – Toy ECC encryption, Caesar cipher and their attacks

Educational toy code. Elliptic curve: real secp256k1 (y² = x³ + 7 over a 256-bit prime), but the private key is restricted to 1…65535 so that attacks are feasible in the browser. Note: the tiny curve mod 17 of HMWK 1 has a group of order 9, too small to encrypt anything, so here we keep the same curve equation and use the real secp256k1 parameters.

1. Toy ECC encryption (EC ElGamal)

Algorithm.
  1. Keys. Private key d (secret integer, here 1…65535). Public key Q = d·G (a point). G, the curve and Q are public.
  2. Encoding. Each character code m (0…255) becomes the point M = m·G (computed from a small table). This is a simple toy encoding, not a standard one.
  3. Encryption. For each character pick a fresh random number r (the ephemeral key). Send the pair C₁ = r·G and C₂ = M + r·Q. The term r·Q acts as a one-time mask.
  4. Decryption. Compute d·C₁ = d·r·G = r·Q (the same mask, because d·Q-type products commute), then M = C₂ − d·C₁, then look up m in the table.
Role of the keys. Anyone can encrypt with the public key Q. Only the owner of d can remove the mask r·Q, since from C₁ = r·G and Q = d·G one would have to solve the discrete logarithm problem.

4. Statistical cryptanalysis of the Caesar cipher

Idea: a Caesar shift moves every letter in the same way, so the ciphertext frequency table is the language table rotated by k. We try all 26 shifts and score each candidate plaintext with three methods: (a) chi-square distance from the English letter frequencies, (b) bigram (2-letter) log-likelihood trained on the corpus below, (c) exhaustive search counting common English words.

7. Discussion

Statistical result. In section 5 the plaintext has an index of coincidence of about 0.065 (English) or 0.075 (Italian) and a χ² far from uniform. The Caesar ciphertext keeps exactly the same index of coincidence (the letters are only relabelled), and the frequency attack singles out one shift whose χ² is far below the other 25, which is the key. The ECC ciphertext has an index of coincidence close to the uniform value 1/26 ≈ 0.038 and a χ² compatible with a uniform distribution; the 26 shifts all get similar scores and the "best" one decrypts to gibberish. Note that the reduction mod 26 is only a device to feed the same tool; a real attacker has no meaningful notion of shift for ECC. This shows the failure of this attack, it does not prove security: security rests on ECDLP.

Caesar attack vs ECC attack. Against Caesar we use statistics of the plaintext language: the ciphertext leaks the letter frequencies, so even without trying all keys the key can be guessed, and the longer the text the more reliable the guess (see the table in section 4: very short texts are ambiguous, a few dozen letters are almost always enough). Against the toy ECC scheme the ciphertext leaks no letter statistics at all, because every character uses a fresh random mask. The attack is instead algebraic / exhaustive: only the small key space is the weakness. We compute multiples of G until we hit Q (brute force, up to 65535 steps) or use baby-step giant-step, which needs only about 2·√65535 ≈ 512 group operations by trading memory for time. Once d is known, all messages encrypted to Q can be decrypted.

Why this fails against a proper ECC scheme. With a uniformly random 256-bit private key the space has ≈ 2²⁵⁶ keys. Brute force would need ~2²⁵⁶ steps; the best generic algorithms (baby-step giant-step, Pollard rho) still need about √(2²⁵⁶) = 2¹²⁸ operations, which is beyond any feasible computation. No statistical structure of the message helps, since ciphertexts are randomised.

Weaknesses from the restricted key space. Few possible keys → exhaustive search and BSGS (cost ≈ √N). Also small r: if the ephemeral number were also drawn from a small range, an attacker could recover r from C₁ = r·G and compute M = C₂ − r·Q without the private key.

Weaknesses from the toy design. (1) Encoding m as m·G and a per-character ciphertext of two points: huge expansion and no real message format. (2) Malleability: adding G to C₂ changes the plaintext from m to m+1 without knowing any key, since there is no authentication. (3) If r is ever reused, C₂ − C₂′ = (m − m′)·G reveals the difference of two characters. (4) A weak random generator for r would be fatal. Real systems use ECIES/ECDH with a key-derivation function and authenticated symmetric encryption, plus 256-bit random keys.
